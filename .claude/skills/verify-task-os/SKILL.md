# Verify task-os

Generated by project-scaffolding's `scripts/gen_verify_skill.py` (`docs/verify-skill.md` there). Text between the `gen:begin` / `gen:end` marker comments is regenerated; the `## Gotchas` section and anything outside the markers is yours and survives regeneration.

Start with the feature map: `features/README.md` lists every feature, and each `features/<view>.md` says how a user reaches it and which test drives it. Run the sections in order: Launch, Doctor, Drive, Evidence, Cleanup. Run Cleanup even when an earlier step fails.

## Launch

Reach a usable state from an **empty** data directory, on a disposable instance. Never against the live app.

1. **Scratch folder.** Make a fresh empty folder in your session scratchpad. It holds the disposable instance's data and your evidence, and Cleanup removes it.
2. **Isolate the data.** Point `TASK_OS_DATA_DIR` at that scratch folder before anything boots, so no database or config of the live app is read or written.
3. **Boot** with the repo's own disposable instance, `tests/e2e/conftest.py::_boot`: the e2e suite's session fixture calls it, so the Drive nodes boot one for you. For a standalone instance, read its signature, call it from a throwaway script in your scratchpad with your scratch folder, and record the PID and port it gives back.
4. **Refuse an occupied port.** The disposable instance must never share the live port (`:8448`). If the port you were given is held, stop and say so; never kill the holder to free it.
5. **Never set `TASKOS_E2E_LIVE`.** That is the opt-in that points the suite at the live app. It stays unset, and a guard refusal is a hard stop, never something to bypass.
6. **Ready means** `GET /healthz` on the disposable instance returns 200. Anything else is a failed Launch, not a slow one: read the instance's log in the scratch folder and report it.
7. **Never touch the tray.** Do not run `tray.bat` or restart anything; the live app is not yours to restart.

## Doctor

Read-only. Report each check as exactly one of `ok`, `stale` or `unknown`. A check that could not be established is `unknown`; never fold it into `ok`. Doctor restarts nothing.

1. **Venv.** `Test-Path .\.venv\Scripts\python.exe` must be true. Invoke Python as `& .\.venv\Scripts\python.exe`; never activate it, never create another.
2. **Browser.** The real test is launching one:
   ```
   & .\.venv\Scripts\python.exe -c "from playwright.sync_api import sync_playwright as p; x = p().start(); x.chromium.launch().close(); x.stop(); print('browser=ok')"
   ```
   A failure that mentions a missing executable means `playwright install chromium` is needed: report it, do not install it unasked.
3. **Disposable port.** The disposable instance must not use the live port (`:8448`). Confirm the boot recipe picks its own free port; if you cannot tell, that is `unknown`.
4. **Live build vs HEAD.** Read-only `GET /api/version` on the live app (`:8448`, loopback), compared with `git rev-parse HEAD`:

```
@'
import json, ssl, subprocess, urllib.request
PORT = 8448
head = subprocess.run(["git", "rev-parse", "HEAD"], capture_output=True, text=True).stdout.strip()
ctx = ssl.create_default_context()
ctx.check_hostname = False
ctx.verify_mode = ssl.CERT_NONE  # loopback only
state = "unknown"
for scheme in ("https", "http"):
    try:
        with urllib.request.urlopen(f"{scheme}://127.0.0.1:{PORT}/api/version", timeout=3, context=ctx) as r:
            sha = str(json.load(r).get("git_sha") or "")
    except Exception:
        continue
    if sha and head:
        state = "ok" if head.startswith(sha) or sha.startswith(head) else "stale"
    break
print("live_version=" + state)
'@ | & .\.venv\Scripts\python.exe -
```

`ok`: same commit. `stale`: different (a squash-merge can change the sha while the content is identical, so diff the content before concluding the wrong code is live). `unknown`: unreachable or no version endpoint. A stale or unknown live app does not block the disposable run; report it.

<!-- gen:begin cleanup -->
## Cleanup

Run this last, and also after a failure.

1. Close every browser and browser context you opened.
2. Stop **only** the instance you booted, by the PID and port you recorded at Launch. Never kill by image name (`taskkill /IM`, `Stop-Process -Name`, `pkill python`): other apps and the live tray run the same executables.
3. If the repo vendors `tests/e2e/_browser_sweep.py`, use it to find leaked browsers: it classifies before it kills and reports what it cannot establish as unknown.
4. Remove the scratch folder, then confirm the disposable port is free again.
5. Leave the live app and its tray exactly as you found them.

## Maintain

Keep the feature map true to the source and the live app. Run from the project-scaffolding checkout (`<scaffold>` below), which owns the generator:

1. **Static half.** `& <scaffold>\.venv\Scripts\python.exe <scaffold>\scripts\gen_verify_skill.py --repo <this repo> --check`. The last line is `STATIC=clean`, `STATIC=changed` or `STATIC=blocked` (exit 0 / 1 / 2). It names new `surface()` names not in the map, mapped names whose test is gone, and changed selectors.
2. **Live half.** Launch a disposable instance, then Drive all mapped nodes with `--junitxml <scratch>/maintain.xml`, then Cleanup.
3. **Verdict.** Re-run the check with the evidence: `--check --live-url <base url of the disposable instance> --junit <scratch>/maintain.xml`. The last line is `MAINTAIN=clean`, `MAINTAIN=changed` or `MAINTAIN=blocked`.

- `clean`: the map matches the source **and** the instance answered **and** every mapped node passed.
- `changed`: the map is stale. Fix it in one PR that touches only this skill's files (regenerate, review the diff, fill gotchas). Never edit a test, delete a journey or loosen a selector to make a drive pass.
- `blocked`: boot failed, the app was unreachable, the live guard refused, a Doctor check was `unknown`, the `[verify]` table has a `FILL:` placeholder, or a mapped node is red. A red node is a possible regression for a human to decide on, not map drift. An unreachable app is never `clean`.

## Gotchas

Add one line per trap you hit while driving the app: the symptom, then the fix. Regeneration never touches this section.

- **Boot through `_boot`, never a hand-copied config.** `TASK_OS_DATA_DIR` only moves the default database folder. The config is read from `TASKOS_CONFIG_PATH`, else `config/config.json`, and the sample's placeholders point the mirror and backup at the real synced folder. `_boot(work, db_path)` writes a blanked sample copy and sets `TASKOS_DB_PATH`, `TASKOS_CONFIG_PATH` and `TASKOS_CLOCK`. A standalone instance is a throwaway script in the scratchpad that puts the repo root on `sys.path`, imports `tests.e2e.conftest`, and calls `_boot(scratch / "work", scratch / "work" / "tasks.db")`.
- **The disposable build line is a fixture.** `_boot` pins `TASKOS_BUILD_SHA=e2e0000` and the clock to 2026-09-07 09:00, so `GET /api/version` reports `git_sha: e2e0000` whatever `HEAD` is. Quote that next to `git rev-parse --short HEAD` and say it is the fixture pin; do not read it as a stale build.
- **The shared work root is `%PUBLIC%\taskos-e2e`, held by one run at a time.** A second `pytest tests/e2e` (another checkout, or the gate) stops with `another e2e run is using the shared work root` and names the holder: wait, never delete the lock. Do not point `PUBLIC` at the scratchpad to avoid it: stories 09 and 10 print the work path, and `shot()` refuses a page that renders the account name.
- **The recorded PID is a launcher stub.** The venv `python.exe` spawns the real interpreter, so the port's listener is a child of the PID `_boot` gave back (plus a `conhost`). Cleanup: check the listener's parent is your PID, then stop the child and the parent by PID. A port that still listens afterwards means a PID was missed, not a slow shutdown.
- **A Drive run rewrites tracked shots only if the capture drifted.** `docs/screenshots/` is the committed baseline, so `git status` after Drive must show none of it. A drifted PNG is a finding to report, not something to commit; restore with `git checkout -- docs/screenshots`.
- **The live app reads `stale` after any merge** until the tray is restarted, and Doctor never restarts it. Report it and carry on: it does not block the disposable run.
- **`browser sweep ... wedged:out-of-scope=N`** at the end of a run counts browsers that belong to other checkouts or sessions. It is report-only; do not kill them.
- **Cost:** the generated Drive command runs whole files serially, 8 nodes, about 2.5 minutes on a quiet box (145 s measured). The gate runs the same suite on four xdist workers.
