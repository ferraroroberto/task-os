## This repository

Personal open-source task manager: FastAPI + SQLite + vanilla-JS PWA + pystray tray, PC-first, port **8448**. See `README.md` for setup, the feature index and the step roadmap (issue #1); the per-feature reference, layout, config and data model live in `docs/<topic>.md`, linked from it. Every build step is a GitHub issue ("Step N/13") whose user story is proven on screen before it closes.

**Project specifics:**

- **Stack is fixed:** Python 3.14 (`py -m venv .venv`; invoke `& .\.venv\Scripts\python.exe`, never activate), FastAPI + uvicorn, stdlib `sqlite3` (WAL, FTS5, one `get_db()` `Depends` — zero per-handler `sqlite3.connect`), vanilla JS (no bundler/framework), pystray. No Docker. Windows-first.
- **Public repo, personal project.** No employer, workplace, colleague names, internal paths or ID schemes anywhere — code, docs, issues, commits, screenshots, fixtures. Generic wording only ("a second site", "a shared install for a small team", "another machine").
- **Personal data never gets committed.** `data/` (SQLite, avatars, backups, logs), `config/*.json` (real), `.env`, `mirror/`, `webapp/` are gitignored; committed twins are `config/*.sample.json`. Screenshots, e2e fixtures and validation transcripts use the **synthetic seed** `tests/fixtures/seed.py` only — it is the one dataset allowed on screen (`seed_db(path)` / `python -m tests.fixtures.seed --db … --reset`; deterministic, anchored on `--anchor`; refuses a DB that already has tasks). Never a real import. Run `git status` before every commit and check nothing private is staged.
- **Visual identity = the fleet's.** Tokens from `~/.claude/design.md` + `design.dark.md` as CSS custom properties (`:root` light, `[data-theme="dark"]` dark, pre-paint stamp in `index.html`, keys `task-os.theme` and `task-os.textsize` — the vendored text-size boot, #314). Components vendored byte-for-byte from `project-scaffolding/app/webapp/static/_vendored/` and recorded in `.fleet.toml [vendored]` — never edit a vendored file per-app; `/propagate-vendored` re-vendors. Lucide sprite inline in `index.html` (per-app trim; glyphs missing from the scaffold sprite pasted verbatim from lucide-static). **No emoji as UI icons.** The one deliberate deviation: **PC-first, width by the shape of the view** (design.md Layout, fleet-config#1113) — `main.app` has no 772px cap on desktop, and the two-dimensional tabs Board and Today span the window (declared in `.fleet.toml [design] wide_views`: all Board columns side by side, drawer as a right-hand panel), while the one-dimensional Time and Search panes keep the 772px measure (`--layout-measure`, capped on `#paneTime`/`#paneSearch`) and Settings is the vendored `settings-group` page, a modal whose column is the same measure (its row sheets are modals; the Email archiving report's, a wide table, spans the window; `tests/e2e/test_story_01_open.py`, its desktop leg; from 1100px on a fine pointer the vendored nav is a left rail and the column fills the rest); the phone is the second, adaptive rendering (bottom pill from the vendored nav).
- **Surface map.** A PR that changes what a person can see or do (a screen, menu, sheet, dialog, gesture, key or Settings row) updates its entry in `docs/ux-surfaces.yaml` (the single source; `python scripts/ux_surface_map.py` regenerates `docs/ux-surface-map.md` and its per-area diagrams, which is never edited by hand) in the same PR and keeps the surface root's `data-surface` id in step with its entry (`scripts/ux_surface_ratchet.py` holds the two together, and fails a page that is not what the YAML generates); what an entry records is stated on the generated page.
- **Every step ships its user story with proof** (`docs/validation.md`): (a) hermetic unit tests + **one** Playwright e2e test `tests/e2e/test_story_NN_<slug>.py` walking the story against a disposable instance and saving numbered screenshots to `docs/screenshots/story-NN-<slug>-<n>-{desktop,phone}.png` (1440×900 desktop first, 390×844 phone where relevant, light and dark) — **always through `tests/e2e/conftest.py`'s `shot()`, never `page.screenshot`**, so two runs of one commit produce the same files **and a run months later still produces the files git is holding** (`scripts/shot_determinism.py` proves the first, its `--check-tree` the second; the five capture rules live in `docs/validation.md`); (b) a headed / real walk by the agent of the same story; (c) the `docs/validation.md` entry — story · steps · expected · screenshot links · test name · result · date. `[x]` in a PR test plan means "walked and seen". Anything not walked is written **not verified**, never as passed. Keep the e2e suite **under 15 tests total**, counted as collected test functions (`pytest tests/e2e --collect-only -q` — the unit the fleet's `e2e_test_audit.py` measures), not files; delete before adding. **Already over that target: 16 collected across 16 files** (held there by `.fleet.toml [e2e] test_budget`), so the next e2e test must first remove or fold one (precedent: fold a leg into its sibling test — #96, #279, #457).
- **Verification — the pre-ship gate is `& .\scripts\verify-before-ship.ps1`** (byte-compile → ruff → static ratchet → docs ratchet → structure ratchet → instruction ratchet → doc-refs ratchet → dead-code ratchet → conventions ratchet → comment ratchet → request budget ratchet → windows-only ratchet → pytest → routed e2e → gallery baseline). Each ratchet is a vendored `scripts/<kind>_ratchet.py`, configured in `.fleet.toml [<kind>_ratchet]` with baseline `.<kind>-ratchet-baseline.json`; it reads the whole tree (never path-routed) and is called only through `python -m scripts.<kind>_ratchet_gate`, where exit 3 (a detector could not run) is NOT CONFIRMED, never a pass or a skip. Shrink a baseline in the PR that removes debt (`--update-baseline`); adding to it needs `--allow-additions` and shows in review. Rule definitions: `project-scaffolding`'s `CLAUDE.md` and `docs/<kind>-ratchet.md`; this repo's specifics: **Static** (#493): a duplicate block (jscpd via `npx`, so **Node is a prerequisite**), an unused import/variable (ruff `F401,F841`) or a likely-bug / security pattern (curated ruff `B` and `S`, `S113` strict) not in the baseline. **Docs**: the validation record (`docs/validation.md`, `docs/validation/**`) is dated by contract and excluded; a new doc states the present-tense why in words, not a `#N`. **Structure** (`shape = "webapp-tray"`, `[structure_ratchet]`): no `extra_roots` is declared today; a new root folder goes in `extra_roots`, never allowed by default. The baseline holds every offender at its real size, never an exclusion; `tests/` sits one module under its cap, so a new test goes in a domain subfolder (`tests/archive/`, `tests/tasks/`, `tests/gates/` …) and a new `src/` module in a domain subpackage; `docs/layout.md` says where new code goes. **Instruction**: a prompt-audit lint hit or size-cap breach in `CLAUDE.md`, `AGENTS.md` or a `SKILL.md`. **Doc-refs**: the hub and whisper ports the docs name on purpose are in `allow_refs`. **Dead-code**: matching is by name; route handlers, `__all__`, tests and decorated hooks are never reported. **Conventions**: `no-window` (a reasoned `# no-window-exempt: <why>` marker exempts one call), `logging-not-print`, `no-drive-path`, `subprocess-timeout` (a foreground runner carries `# subprocess-timeout-exempt: <why>`) and `host-identity` (tests use `tests/host/_synthetic_host.py`'s `synthetic_host`, never `getpass.getuser`, `Path.home()`, `expanduser` or the account/home environment variables; a deliberate privacy check or live-install guard carries `# host-identity-exempt: <why>`); `secret-compare` and `git-wrapper` stay off because the repo has no helper to route through. **Comment**: no `#NNN` issue reference inside product-code comments and Python docstrings (`.py`, `.js`, `.css`, `.ps1`; other strings, tests and vendored files are left out), the baseline being empty — a comment states the present-tense why in words, history stays in the issue and `git log`. **Request budget** (`[request_budget_ratchet]`): a loop that must run while nobody is viewing is declared in `[[request_budget.loops]]` with its reason. The baseline is empty: the web app runs the vendored `request_timing` middleware, a new browser poll uses the vendored `poll` helper, and a hit is fixed, declared or exempted with its reason, never baselined. The runtime half is story 01's last leg (vendored `tests/e2e/budget/_request_budget.py`): a fake-clock minute visible, within `.fleet.toml [request_budget] visible_requests_per_minute`, and a minute hidden that sends only the usage log's one hide beacon; a missing budget key is NOT CONFIRMED. **Windows-only** (`[windows_only_ratchet]`): mark the test with the `windows_only` marker the Mac nightly deselects, or write `# windows-only-exempt: <reason>` on a hit the ratchet gets wrong, never raise the baseline (empty today). The e2e phase boots its **own disposable webapp** on a free port with `TASKOS_DB_PATH` → temp DB and `TASKOS_CONFIG_PATH` → the sample config; it never touches the live `:8448`. `TASKOS_E2E_LIVE=1` is the one loudly-named opt-in for read-only assertions against the live instance (never a kill). Browser routing is diff-proportionate via `scripts/classify_e2e.py` + `.fleet.toml [e2e]` (static-asset diff → Chromium smoke; backend/docs-only → no browser suite; anything UI/behavioural or unmatched → full). The last stage compares whatever shots the e2e phase rewrote against the committed gallery and restores them (`scripts/shot_determinism.py --check-tree`, #225): `docs/screenshots/` is a **baseline**, so a UI change owes it a deliberate re-baseline (`pytest tests/e2e`, review, `git add docs/screenshots`) and a verification run never leaves rewritten PNGs behind. **Runtime contract (measured 2026-10-03 on a quiet box, #288):** the unit leg ≈ 2.1 min (786 tests); the full routed e2e ≈ 55 s (16 nodes, one Chromium projection, on **4 pytest-xdist workers**: `-n 4 --dist loadfile`, passed by the gate for the full tier only) against ≈ 2.5 min serial (`TASKOS_E2E_WORKERS=1` is the serial control, any other number overrides the four; more workers gain only ~10 s); the whole gate on a full-tier diff ≈ 3.1 min (4.7 min serial). A run over 1.5× those figures is a loaded box or a regression, not normal. Every full-tier e2e run writes `data/e2e-junit.xml` in the primary checkout, from a worktree too (`scripts/e2e_record_path.py`; `TASKOS_E2E_JUNIT` names another file), which `.fleet.toml [e2e] junit_xml` hands to `/e2e-audit` as its per-test timing source. - **Design inventory (fleet-config#1383):** every surface a story opens carries `surface(page, "<tab>.<surface>")` (vendored `tests/e2e/_surface.py`, `[vendored] surface_capture`; `[design.review] theme_storage_key` lets it flip the app's explicit theme). It is inert on every normal run. `/design-review measure task-os --e2e` arms it on its own disposable instance and keeps only the tests whose **own body** calls `surface(` (a call inside a helper does not select its test, so story 01 tags its fresh-install Today in the test body). A transient popover that closes on scroll can lose its open state to the capture, so tag it only when the test does nothing with it afterwards.
- **Restart recipe (long-lived process, no hot-reload):** after the gate passes, run `.\.venv\Scripts\python.exe -m src.restart_check restart --port 8448` (`./.venv/Scripts/python.exe` in Git Bash; same in every shell; run it in the foreground). It runs this checkout's `tray.bat --restart` by absolute path and exits non-zero unless a different process serves `HEAD`; the bat is the orphan-proof reclaim-then-start owned by the shared `%USERPROFILE%\.claude\tray\tray_lifecycle.ps1` (fleet-config): kills the tray subtree, reclaims `:8448` by PID scoped to this repo's `.venv`, starts fresh. Never hand-roll the kill. Never type the bare `tray.bat --restart`: it is not found from any shell here (by hand only `.\tray.bat` in PowerShell, `./tray.bat` in Git Bash), and Git Bash `cmd.exe /c "tray.bat --restart"` exits 0 having restarted nothing. **The build-identity check is `GET http://127.0.0.1:8448/api/version` → `git_sha == git rev-parse --short HEAD`** (a `/healthz` 200 passes on a stale process; a matching SHA does not) — poll bounded (≤30 s), report the build line, never hand off "done" over a stale process. One long-lived component (the webapp under the tray); nothing is excluded from the restart.
- **Config & secrets:** `config/config.json` (gitignored, sample committed) — `site`, `port`, `issues`, `placeholders`, `mirror`, `search`, `calendar` (`ics_url` — a secret: host only anywhere it is shown or logged, #96; `refresh_minutes`, `timeout_seconds`), `team` (`enabled`, `people`, `password_hash` — the last written only by `scripts/set_team_password.py` via `save_team_password_hash()`), `people` (`[{id, name}]`, #474 — the install's members, the first is the install owner; absent = `time.people`, else one implicit member `me`; once present it also replaces `team.people` as the name-step list), `time` (`people` as `[{id, name}]` — the deprecated spelling of `people`, still read first for Time; rows store the id, never the name; `compare_area`, `long_timer_minutes`; #457), `auth` (`token`, `password_hash` — the owner's legacy hash, used only until the vendored `src/password.py` stores one in `config/app_password.json` via `python -m src.password set` — and `people.<member id>.{token, password_hash}` for every other member, #474; written only by `scripts/gen_token.py` / `scripts/set_password.py --person <id>` via `save_auth()`; a secret whose id is no longer a member is ignored at load; the sample keeps every secret empty and team mode off). `.env` only for the Notion import token. `src/config.py` falls back to the sample when the real file is missing so a fresh clone boots — **with the mirror and backup off** (the sample's placeholders resolve to the real synced folder; a config-less checkout such as a git worktree must never write into it — #126). The same folder is refused by construction for any instance on `TASKOS_DB_PATH` whose mirror / backup dir is not beside that database.
- **Access & HTTPS (Step 7):** `src/auth.py::AuthMiddleware` is the one gate — **loopback is the owner** (no credential), any other client needs the bearer token (`Authorization: Bearer` or the `taskos_token` cookie `/login` sets for 90 days); no token configured = closed for non-loopback, never open. **One token per person (#474):** `auth.token` and the owner's password (`AuthConfig.owner_password_hash`: `src/password.py`'s hash, else the legacy `auth.password_hash`) stay the owner's; each other member's own token passes the same gate and `/login` hands it back as their cookie, and the middleware puts who the request is on `scope["state"]["viewer"]` (`src/auth.py::resolve_viewer` → `GET /api/me`) — read only from a credential that already passed; plain loopback = the owner. **Team mode (Step 12, `team.enabled`, off by default)** only *adds* the `taskos_team` cookie the team password buys (derived from the token, never the token itself) — it must never loosen the rest, and off must stay byte-for-byte the Step 7 model; the picked name (`src/team.py`, `taskos_name`) is an authorship label in `resolve_actor`, never a credential. Public on any client: `/static/`, `/healthz`, `/api/version`, `/login`, `/api/login`. New `/api/` routes are gated by construction — do not add per-route exemptions; a route that must be public goes into `src/auth.py`'s `PUBLIC_*` with a reason. **Tests:** the disposable e2e instance binds `127.0.0.1`, so the browser is the owner and needs no token — there is deliberately **no `TASKOS_AUTH_DISABLED` switch**; unit tests spoof a non-loopback address (`TestClient(app, client=("100.x", 1))`) to exercise the gate and pass `client=("127.0.0.1", …)` for the owner (starlette's default `testclient` host is *not* loopback). The cert pair lives at `webapp/certificates/{cert,key}.pem` (gitignored; `scripts/gen_tailscale_cert.py`, copied from `project-scaffolding` and adapted here, not vendor-verbatim — project-scaffolding#232); `src/certs.py` decides HTTPS vs plain HTTP for **every** spawn point and runs `--check` (auto-renew) before uvicorn binds. There are two: `manager.py` under the tray and `scripts/launcher.py webapp` — keep them agreeing. `scripts/webapp.bat` is a venv-finding wrapper over `scripts/launcher.py webapp`, so it cannot disagree; never re-implement a spawn there. The tray opens / copies `https://<host>.ts.net:8448` (from the cert's SAN); the restart probe stays on loopback. Never put the MagicDNS hostname or a token in the repo — docs say `<your-host>.ts.net`.
- **Schema versioning:** `src/schema.py` owns every DDL as `MIGRATIONS[version]` and `migrate()` applies the pending steps (each in its own transaction with its `settings.schema_version` stamp); `src/db.py::init_db()` runs it at every startup, the CLI's local backend too. A schema change = a new entry (never edit a shipped one) + a bump visible in `/api/version`. `TASKOS_DB_PATH` overrides the DB path (tests, seeds, the e2e instance).
- **Domain rules live in the `src/tasks/` package, nowhere else** (`schema.py` the shared foundation, `queries.py` reads, `mutations.py` task writes, `related.py` comments / links / issue refs / people writes; `src/tasks_repo.py` re-exports it all, so callers still say `tasks_repo`) — the routers, the CLI's local backend and the seed all call it (activity on every change, cycle guard, recurrence roll, `coding` ⇔ issue_ref, FTS via triggers). Adding a rule to a router or the CLI is the wrong layer. Repo errors (`NotFound` 404 · `ValidationError` 422 · `CycleError` 409) become the one JSON envelope `{"error": {"code", "message", "detail"?}}` through the app-level handlers in `server.py`.
- **Time-tracker rules live in `src/time_repo.py`, nowhere else** (#457) — `routers/time_tracker.py` and `scripts/import_time_prototype.py` call it; nothing else writes the `time_*` tables. One running timer per person; start / stop / switch / discard are each one `BEGIN IMMEDIATE` transaction (a stop deletes the timer and inserts the entry together); a clocked entry's end is always start + minutes, and an entry with no clock range (imported) never gains one; the day is the day an entry *started*, in the server's zone — the client takes `today` from `/api/time/meta`; areas and categories are archived, not deleted, and a category still in use is never removed (#463). People are `config.time.people` ids, a per-device label, never a credential. Its errors subclass `RepoError` (`timer_running` / `no_timer` / `slug_taken` / `category_in_use` 409).
- **Federated search (`src/search/`, Step 10):** one adapter per index behind `base.py`'s contract; `federated.py` runs them concurrently and **always returns the four groups** — an unconfigured index is `configured:false` + reason, never absent; a broken one carries `error`. Folders and emails are folder-explorer's v1 search API through `src/search/folder_explorer.py` (`search.folder_explorer_url`; no index, vendored searcher or email-DB read here): five states — `ok` · `indexing` · `not-configured` · `failed` · `unreachable` — and anything but `ok` is `Unavailable`, a group's `unavailable: {state, reason}`, never an empty list; the client reports the states as folder-explorer sends them and carries no workaround for its misreports. Tests never call the real one: `write_test_config` blanks `search.folder_explorer_url` and the search tests point it at `tests/fixtures/folder_explorer_fake.py`. No forge call from the issues adapter — it reads `issue_refs` + the sync's cache.
- **Capture is push, and one-way (`src/email_capture.py`, #98):** anything marked in another channel lands in Inbox on its own. Both channels dedupe on `tasks.external_id` through the one repo rule `capture_task` — an *import* reconciles, a *capture* only ever lands, so a re-run never edits, closes or deletes what it made (un-flagging an email does nothing; `POST /api/tasks` with an `external_id` answers 201 once and 200-with-the-same-task forever after). The key also lives in `capture_keys` (v17), which has no FK and outlives the task: **deleting a captured task dismisses it** — `capture_task` answers `(None, "dismissed")`, the pass counts it, the POST replay is 410 `capture_dismissed` (#254). Anything that re-keys a capture (`rename_external_id`) moves that row too, with or without a live task. The email side pages folder-explorer's `GET /api/v1/mail/flagged` through `FolderExplorerClient`, **the same client the search adapter uses** (no database read — `tests/search/test_no_folder_explorer_file_reads.py` forbids one) — keyed on `email:` + the folded `.msg` ref, never a row id (a rowid that reshuffles on an index rebuild). The flag state is the **archiver's** to write; when the client answers anything but `ok` the poller reports that state (*not configured*, *indexing*, *unreachable* …) with its reason, never an empty result. A stored `links(kind=email)` row holds the **ref**, not a built `taskos://` URL — `format.js::chipFor` keys on the leading `{` to derive the opener href itself, and a URL there renders an hrefless web chip.
- **`tasks` CLI (`src/cli.py`, `tasks.bat`)** talks HTTP when the app answers, else opens the DB directly; both backends return the API's shapes so `--json` is identical either way — a key the offline backend genuinely cannot establish (`https` and `auth.client`, which describe a live *request*, not the install) is present carrying `cli.UNKNOWN` (`"unknown"`, the literal the API itself already emits for an unclassifiable `auth.client`); never dropped, and never inferred from the config, which would report a fact nobody confirmed. Natural dates go through `src/dates.py` (also the future quick-add parser) — extend the parser there with a test, never inline a date phrase elsewhere.

## CI expectations
- No hosted workflow. The Mac Mini nightly (`project-scaffolding`'s `nightly-mac`, this repo's `[ci.nightly]` table in `.fleet.toml`) is the one CI. It runs when `main` moved since the last green night, and every Sunday: a fresh `.venv`, the unit suite without the `windows_only` tests, and the e2e suite on Playwright WebKit with the iPhone projection.
- **Advisory, not a merge gate**: a PR starts no run, so the local gate (`scripts/verify-before-ship.ps1`) is the per-change contract and `/issue-finish` has no CI run to wait on.
- A red night opens one `ci-red-main` issue here, closed by the next green night. A test that passes only on its one retry is recorded as flaky, not red.
- Only the local gate covers the `windows_only` tests (tray, PowerShell gate, cmd opener) and the Chromium run of the stories.
- The runner has no gitignored config: the nightly seeds `config/*.sample.json` to their live names, and nothing reads the live `:8448`, a real mirror folder, the real folder-explorer or the archiver's `emails.db`.
