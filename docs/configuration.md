# Configuration — `config/config.json`

| Key | Meaning |
| --- | --- |
| `site` | `home` or a second site name — a label; nothing keys on it (the forge is `issues.provider`, the synced folder is `placeholders` / `mirror`) |
| `port` | webapp port (default **8448**) |
| `issues` | `provider` (`github` · `gitlab`; blank = off), `owner` (GitHub: whose repos are searched · GitLab: the group path, sub-groups included), `assignee` (`@me` or a username), `sync_minutes` (default 10), `host` (GitLab only: the hostname of a self-hosted instance; blank = `gitlab.com`). See [Issues as tasks](issues-as-tasks.md#issues-as-tasks) |
| `placeholders` | `onedrive`, `user`, and a `sharepoint` map (`{"docs": "E:/…"}` → `{sharepoint:docs}`) — what **this** server expands folder refs with for display; the opener on each PC expands the same tokens from its own environment. See [Folders that open on any PC](folders.md#folders-that-open-on-any-pc) |
| `web_roots` | optional cloud *web* equivalent per placeholder, same shape (`{"onedrive": "https://…", "sharepoint": {"docs": "https://…"}}`). A ref starting with a mapped token gets its provider **web URL** derived (root + the percent-encoded rest) as `folder_url` — the phone popover's **Open web link** — unless the task carries an explicit folder web link, which always wins. Empty (the sample) = no derivation. Only refs whose root has a web twin are covered |
| `mirror` | `dir` — the markdown mirror folder (one `.md` per task); `backup_dir` — where the dated `.db` copies go. Both take `{placeholders}`; either blank / unresolved / with a missing parent folder = that service off, with the reason in `/api/status` and `tasks mirror status`. Both stay off when the app runs on the committed sample (no `config/config.json`) or on an overridden database (`TASKOS_DB_PATH`) whose folder they are not inside — see the provenance rule under [Markdown mirror](mirror-and-backups.md#markdown-mirror) and [Backups](mirror-and-backups.md#backups) |
| `search` | `folder_explorer_url` — [folder-explorer](https://github.com/ferraroroberto/folder-explorer)'s address: the Folders and Emails groups call its v1 search API, task-os holds no index of its own. Leave the key out and it is folder-explorer on this PC (`https://127.0.0.1:8453`, self-signed, so the loopback certificate is not verified); set it to override (another machine, another port); set it to `""` to turn Folders and Emails off — both then say *not configured*. Either way, folder-explorer not answering is its own *unavailable* state; `email_deep_url` — folder-explorer's page (`https://<your-host>.ts.net:8453/`): set, the Emails group ends with *Search all mail in folder-explorer*, its own email search for the same words; blank = no link. See [Search everything](search.md#search-everything) |
| `capture` | `email_poll_minutes` — how often the flagged-email poller asks folder-explorer's `GET /api/v1/mail/flagged` for the flagged mail (default 10; `0` = off, visibly). No address of its own: it calls `search.folder_explorer_url`, with a 10 s timeout (a pass runs on a background thread, so it can wait longer than the Search tab). An older config that still carries `search.email_db` is ignored with one info line at startup. See [Capture into the Inbox](inbox.md#capture-into-the-inbox) |
| `voice` | `transcribe_url` — where a recorded quick-add line is forwarded (default `http://127.0.0.1:8000/v1/audio/transcriptions`, the [local-llm-hub](https://github.com/ferraroroberto/local-llm-hub); it names no model, so the hub applies its transcribe role — parakeet first); blank = voice off, visibly. `fallback_url` — the local whisper server, tried **only** when the hub cannot be reached at all (default `http://127.0.0.1:8090/v1/audio/transcriptions`; blank = no fallback). `partial_interval_seconds` — how often the page re-posts the take so far so the transcript appears while you speak (default `1.5`; `0` = one transcription on stop). See [Voice quick-add](voice.md#voice-quick-add) |
| `enrich` | `url` — the hub's chat endpoint, where a **spoken** line goes to be split into a title and a description (default `http://127.0.0.1:8000/v1/chat/completions`; blank = enrichment off, visibly, and the spoken line keeps the plain parse). `model` — named on purpose here, unlike transcription (default `agentic_light_nothink`). `timeout_seconds` (default 30). See [Voice quick-add](voice.md#voice-quick-add) |
| `ai` | local AI shared by task workflows: `enabled`, `base_url` (default `http://127.0.0.1:8000`), `model` (default hub alias `claude_haiku`) and `timeout_seconds` (default 30). The first consumer is [AI Inbox triage](inbox.md#ai-inbox-triage); disabled and unreachable states are visible on the Board, in Settings, `/api/status` and the CLI |
| `archive` | batch-archiving the Outlook Inbox through [folder-explorer](https://github.com/ferraroroberto/folder-explorer)'s v1 archive API at `search.folder_explorer_url` (no address of its own, so there is one folder-explorer per install): `enabled` (**false in the sample** — no checkout without its own config may drive Outlook; on with no `search.folder_explorer_url` reads as off, with that as the visible reason), `candidates` (ranked folders asked of the archiver per mail, default 10 — the model is shown only the **top 6** of them, the rest being noise it would have to read; a `move` can still name any folder at all), `confidence_threshold` (default 0.7 — below it a mail stays in the Inbox as *needs you*), `timeout_seconds` (default 660 — how long one archive call is waited for; a full Inbox is walked over COM, and it stays above folder-explorer's own 600 s budget per verb so a stuck Outlook comes back as its typed `timeout` answer). The ranking adds `model` (which hub model picks the folder, default `claude_haiku`), `batch_size` (mails per hub request, default 8), `examples` (stored corrections carried as few-shot lines, default 20) and `ai_timeout_seconds` (that request's own bound, default 180 — a batch is a far longer request than one triage). `renumber` (default **true**) asks the archiver to re-sequence every folder an `apply` or a `revert` disturbed and heals every path this database stores from the map it returns — see [Renumbering, and the paths it heals](inbox-archive.md#renumbering-and-the-paths-it-heals). The hub root and the on/off switch stay `ai.base_url` / `ai.enabled`. See [Archive the Inbox](inbox-archive.md#archive-the-inbox) |
| `calendar` | the read-only calendar lane on Today: `ics_url` — a **private** ICS address (Google's *secret address in iCal format*, Outlook's published calendar link; `webcal://` is read as `https://`); blank = the lane says *No calendar connected*. **It is a secret** — anyone holding it reads the calendar — so it lives in this gitignored file only, and the lane, Settings, `/api/status`, errors and the log show its host alone. `refresh_minutes` (default 10; a failed fetch is retried after a minute), `timeout_seconds` (default 2 — the bound on a fetch and on how long Today ever waits for one). See [Calendar beside Today](task-workflow.md#calendar-beside-today) |
| `people` | the install's members: `[{id, name}]`, the **first is the install owner**. Ids are what rows and `auth.people` key on, never the name. Absent (the sample) = `time.people`'s list, else one implicit member `me`. Once present, it is also the list team mode's name step offers (replacing `team.people`) and the owner's default name. See [Phone access & auth](access.md#phone-access--auth) |
| `team` | shared install for a small team (Step 12): `enabled` (**false in the sample** — off is the single-owner model unchanged), `people` (the names a teammate picks from; the first is the owner's default name — ignored once a top-level `people` block exists) · `password_hash` (the shared team password, `scripts/set_team_password.py`; empty in the sample). See [Team mode](access.md#team-mode) |
| `time` | the time tracker: `people` (`[{id, name}]` — who tracks time; rows store the `id`, never the name; the sample holds two placeholder people. **Deprecated spelling** of the top-level `people`: still read first for Time, and the members list falls back to it; a missing block falls back to `people`, then to one implicit person `me`, so there is no picker or comparison) · `compare_area` (the area slug the household comparison reads, `home`) · `long_timer_minutes` (how long a timer runs before it asks whether it was forgotten, 180) |
| `auth` | `token` (the install owner's bearer secret, `scripts/gen_token.py`) · `password_hash` (the owner's legacy password hash, used only until `python -m src.password set` stores one in `config/app_password.json`) · `people` (optional: `{<member id>: {token, password_hash}}` — another member's own sign-in, written by `gen_token.py --person <id>` / `set_password.py --person <id>`; an id that is no longer a member is ignored, which signs them out). Every secret empty in the sample = only this PC can use the app |
| `alerts` | where the sign-in guessing alert goes: `notifier` (`none` — the default, no message — or `telegram`) · `telegram_bot_token` · `telegram_chat_id` (the fleet's `coding alerts` chat). A `telegram` notifier missing either value falls back to `none` with a warning. Both are secrets: they live only in the ignored real config, never in the sample. See [Phone access & auth](access.md#phone-access--auth) |

Secrets (the Notion token for the one-shot import — `NOTION_API_TOKEN`, optionally `NOTION_TASKS_DB_ID`) go in `.env` (or any dotenv passed with `--env-file`), never in config; the GitHub side needs no token of its own — it is the `gh` CLI's login. `TASKOS_CONFIG_PATH` / `TASKOS_DB_PATH` env vars override the config/db location, `TASKOS_ISSUE_PROVIDER=none|fake` (+ `TASKOS_ISSUE_FAKE_PATH`) overrides the issue provider, `TASKOS_CLOCK=<ISO datetime>` pins the process clock and `TASKOS_BUILD_SHA=<string>` pins the build identity the `Build:` footer prints (the test harness uses all five for isolation — the last two so the story gallery in `docs/screenshots/` does not rewrite itself on every commit and every calendar day; nothing in normal use sets any of them, and a pinned build SHA is logged as a warning because a process reporting an identity it did not compute is also what would defeat the restart recipe's `/api/version` check).
