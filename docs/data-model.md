# Data model

One SQLite file (`data/tasks.db`, WAL, FTS5), migrated by `src/schema.py` (`settings.schema_version`, currently **20**):

`tasks(id, parent_id, code, title, type task|coding|note, status inbox|todo|standby|done|cancelled, priority high|medium|low|none, due, starts (v7 - the day it starts mattering; see [Start dates & snooze](task-workflow.md#start-dates--snooze)), recurrence daily|weekly|monthly|quarterly|yearly + recurrence_anchor (v9 — the fixed day a weekly/monthly recurrence lands on) + recurrence_interval (v16 — repeat every N cadences, NULL = every one; both: see [Start dates & snooze](task-workflow.md#start-dates--snooze)), description, folder_ref, next_action, person_id, owner (v20 — the member whose task it is, a `people` id; NULL = the install owner, so the step rewrote no row; see [Task drawer](views.md)), created_by, created_at, updated_at, done_at, external_id)` · `links(task_id, url, label, kind web|folder|email|issue|ai)` (v5 adds `ai` — an AI-conversation link, see [AI conversation links](ai-conversation-links.md#ai-conversation-links)) · `comments(task_id, author, ts, body, origin ui|cli|md|notion|import|sync, external_id)` · `activity(task_id, ts, actor, field, old_value, new_value)` · `people(name, email, avatar_path, external_id)` · `issue_refs(task_id, provider, repo, number, state, url, last_synced)` · `mirror_state(task_id, path, exported_at, file_mtime_ns, content_hash)` (v4 — what the markdown mirror last wrote per task) · `mirror_events(task_id, kind conflict|rejected, field, file_value, kept_value, ts)` (v6 — a mirror import conflict/rejection, deduped on task+field+file value; issue #84) · `task_blocks(blocker_id, blocked_id)` (v11 — a *blocks* edge, cascade-deleted on either end; see [Blocked-by dependencies](task-workflow.md#blocked-by-dependencies)) · `ai_suggestions(task_id, payload, status pending|accepted|rejected, created_at, resolved_at)` (v12 — at most one pending suggestion per task; see [AI Inbox triage](inbox.md#ai-inbox-triage)) · `archive_runs(started_at, finished_at, status running|done|failed, planned, archived, needs_review, failed, error)` + `archive_items(run_id, message_id, entry_id, subject, sender, sent_at, attachments, candidates_json, chosen_folder, chosen_rank, confidence, reason, date_prefix, files_json, sequence, status archived|needs_review|failed|reverted|moved, error, decided_at)` (v14 — one row per archiving run and per mail it decided on, with a partial unique index on `message_id` over the two filed states so a mail is filed once; see [Archive the Inbox](inbox-archive.md#archive-the-inbox)) · `archive_corrections(item_id, message_id, subject, sender, suggested_folder, chosen_folder, hint, created_at)` + `archive_runs.agreement` (v15 — every time a human overruled the folder ranking, copied rather than joined so deleting a run never deletes what it taught, and the run's share of picks that matched the archiver's own top; see [Archive the Inbox](inbox-archive.md#archive-the-inbox)) · `capture_keys(external_id, captured_at)` (v17 — every capture key ever landed, no FK so it outlives the task: what keeps a deleted capture dismissed; see [Capture into the Inbox](inbox.md#capture-into-the-inbox)) · `time_areas(slug, name, position, archived_at)` + `time_categories(area_id, slug, name, hint, position, archived_at)` + `time_entries(person, category_id, day, minutes 1–1440, started_at, ended_at — both or neither, note ≤ 140, created_at, updated_at, source_id)` + `time_timers(person PK, category_id, started_at)` + `time_guesses(person PK, pct 0–100, updated_at)` (v19 — the time tracker, seeded with Home · Work · Personal · Health; its rules live in `src/time_repo.py`: one running timer per person, a stop that deletes the timer and saves the entry in one `BEGIN IMMEDIATE` transaction, an end that is always start + minutes, the day an entry *started* as its day, in the server's zone, and areas / categories archived, not deleted — only a category no entry or running timer points at can be deleted, #463) · `tasks_fts` + `comments_fts` (FTS5, trigger-synced).

Rules the repo layer enforces (`src/tasks_repo.py`): a task with children **is** a project (the `project` filter means "descendant of"); `move` refuses cycles; `add_blocker` refuses a self-block and a cycle in its own separate `task_blocks` graph (see [Blocked-by dependencies](task-workflow.md#blocked-by-dependencies)); every due / status / parent / priority (and title, type, recurrence, person, description) change writes an `activity` row, and so does every blocker add/remove, on both tasks; `POST .../done` on a recurring task rolls the **same** task's due to the next occurrence after both that due and today (the `recurrence_anchor`'s fixed day when it has one, every `recurrence_interval`-th cadence when it has one; month-end clamps) and logs the completion, otherwise it sets `done` + `done_at` (the web app reaches this from a recurring task's completion circle, its ⋯ **Complete** and the drawer's **complete** status option; picking `done` in the drawer is always a plain status change — closed for good, recurring or not); `done_at` is the **closed-at** stamp — `cancelled` sets it too and reopening clears it (v10 backfilled older cancelled rows from their activity log), which is what the [done journal](views.md#views) groups by; `type = coding` **iff** an `issue_refs` row exists (attach an issue to make a task coding — setting the type by hand is rejected); a task whose `starts` day has not arrived, or that still has an open blocker, is hidden from the working views by `list_tasks` (see [Start dates & snooze](task-workflow.md#start-dates--snooze) and [Blocked-by dependencies](task-workflow.md#blocked-by-dependencies)); deleting a task deletes its subtree and frees anything it blocked.
