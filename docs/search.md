# Search everything

One box, four indexes, results grouped by kind — a centred 772px column on the PC, one column on the phone. `src/search/` holds one **adapter** per index behind one contract (`base.py`: `is_configured() → (ok, reason)`, `search(q, limit) → hits`); `federated.py` runs the configured ones **concurrently** (a thread pool, 2 s per adapter — a slow folder-explorer cannot hold the tasks answer hostage) and always answers with the four groups in order:

| Kind | Index | Configured when | Hit → open · attach · new task |
| --- | --- | --- | --- |
| **Tasks** | `tasks_fts` + `comments_fts` (title · description · comment bodies), the FTS5 snippet with the match marked | always | open = the drawer |
| **Folders** | [folder-explorer](https://github.com/ferraroroberto/folder-explorer)'s folder search (`GET /api/v1/search/folders`), each hit with its portable ref + this PC's path | folder-explorer is configured (on by default, see [Configuration](configuration.md)) | open = the `taskos://` opener chip · attach = the task's **folder** (or a folder link when it already has one) · new = a task titled like the folder, with the ref |
| **Emails** | [folder-explorer](https://github.com/ferraroroberto/folder-explorer)'s email search (`GET /api/v1/search/emails`) — it ranks and highlights; task-os opens no email database for search | folder-explorer is configured (on by default, see [Configuration](configuration.md)) | the hit is subject · sender · date · folder; its `ref` is the `.msg` path folded onto the placeholders (`{onedrive}/…/mail.msg` when it lies under a configured root) — open = the same opener chip (Windows opens the file with its default app), attach = `links(kind=email, url=<ref>, label=subject)`, new = a task titled like the subject with *From email: sender · date* and the link |
| **Issues** | `issue_refs` joined to their tasks + the sync's cached open list (Step 8) — title, `owner/repo#N`, labels; **never a forge call per keystroke** | the issue provider is | open = the issue URL (or the linked task) · attach = *link existing* (`PUT /api/tasks/{id}/issue`) · new = a coding task with the ref |

**Not configured is a visible state**, never an empty result: the kind is named on the folded line under the results (*Not set up: emails · Settings*; Settings → **Search** lists the four with their reasons and `GET /api/search/status` returns the same); a broken index gets its own line in the danger tone (*Emails failed — …*). **folder-explorer not answering is its own state too**: for Folders and Emails the group carries `unavailable: {state, reason}` with `state` one of `unreachable` (the request failed), `indexing` (its first scan or email build is running), `not-configured` (nothing set up there yet) or `failed` (it could not read its index, or answered something that is not the v1 contract), shown as its own line (*Emails unavailable (unreachable) — …*) and never folded into *No matches*. Settings → **Search** shows the same state per kind. Marked terms come back as `[match]` and render as `<mark>`.

**Search tab** — autofocus box (the header bar's height), 200 ms debounce, `?q=` in the URL while the tab is showing (`/?q=kitchen#search` is a deep link). Before a query the tab is the box and a one-line hint (plus the folded *Not set up* line when an index is off) — no group waits empty. With a query, **a group appears only for a kind with hits**, open, under a quiet uppercase header with its count (*Tasks 2 of 3* when the scope or the filters cut some; no timings on screen); every other kind folds into **one line** under them — *No matches in folders and issues · 3 task hits hidden by the filters or the scope · Not set up: emails · Settings*. **Every hit is the same row shape**: a title line and one muted meta line, no glyphs, no buttons. Task hits are the row every other view shows (circle, meta line, ⋯) plus the matched snippet, narrowed by the **Tasks · Issues · All** switch under the box (Tasks leaves the synced issues' tasks to the Issues group), by the filter sheet the box's filter button opens, and sorted by it, but never by whose they are (search covers everyone); a folder hit is *name · full path* and an email hit *subject · sender · date · folder*, their title being the `taskos://` link (a PC opens Explorer / the `.msg`, the phone shows the path to copy); an issue hit is *title · repo#N · state* — the title opens the linked task when there is one, else the issue page. When `search.email_deep_url` names folder-explorer's page, the Emails group ends with **Search all mail in folder-explorer**, which opens its email search (`#search?mode=emails&q=…`) for the same words in a new tab: operators, facets and Show all live there, and this box stays the quick search. Keyboard: `↓` from the box focuses the first row; on rows `↑↓` move, `Enter` opens, `Esc` / `/` back to the box.

**Command palette** — `Ctrl+K` / `⌘K` anywhere — the header carries no button for it, so the phone reaches it from Settings → **Command palette** (a row and its sheet), whose *Open command palette* button is the same call (the vendored editor-modal shell; a full-width sheet on the phone). Type to **jump to a task** (the tasks adapter, top 8: title · breadcrumb · status; `Enter` opens it); `>` lists **commands** filtered as you type: *New task* (opens the quick-add dialog), *Go to Today / Board / Archive / Search / Settings*, *Filter: status inbox|todo|standby|done* / *Filter: clear* (every view), *Sync issues*, *Rescan folders*, *Export mirror*, *Open folder of current task* (emits the drawer's `taskos://` chip click), *Toggle theme*, *Sign out*. `↑↓` move, `Enter` runs, `Esc` closes.

**Terminal** — `tasks search "q" [--kind emails]` prints one block per kind (unconfigured indexes on their own line) and `--json` returns the API's shape; with the app down it builds the same adapters locally (folders and emails still go to folder-explorer, the issue cache cold — local refs only).
