# Time tracking

The **Time** tab (#457) is a time tracker beside the tasks: Toggl-style personal tracking and, from the same data, a household comparison of who spends how much time on what. It loads nothing until its tab is first opened.

- **Who tracks time** is the `time` block in `config/config.json`: `"time": {"people": [{"id": "p1", "name": "Person 1"}, {"id": "p2", "name": "Person 2"}], "compare_area": "home", "long_timer_minutes": 180}`. Rows store the `id`, never the name. A missing block, or an empty list, is one person (`me`): head-to-head and guess card are absent, just your own tracker. Restart after editing (`tray.bat --restart`).
- **Time logs as whoever is signed in** (#475): `GET /api/time/meta` carries `you`, the member behind the request (their own token or password, or the install owner on this PC, see *Access*), so there is no per-device picker and nothing is stored in the browser (the `task-os.time.person` key an older build kept is ignored and removed). On the API, `person` is optional on `POST /api/time/timers`, `POST /api/time/entries`, the `by-source` PUT and `GET /api/time/recent`: left out, it is the viewer; given, it wins, so the owner can still log for or edit the other person from the PC, and an importer keeps naming its person. A request that is no member (a team sign-in whose name matches nobody) gets 422 `person is required` until it names one, and the tab asks once per visit, in memory. Still a label, not a permission: anyone with access can log or edit any entry. Totals keeps the household comparison and marks the viewer *(you)*; *Me* in Me · Everyone is the viewer.
- **Log** shows today per person, this device's running timer and the start list (Recent first, then each area). A tap starts a timer; a tap while one runs offers **Stop and start …** as one call. Timers live on the server: a reload or a second device shows the same one, two people can each have one at once, and a second timer for the same person is refused (409). Past `long_timer_minutes` the card asks whether the timer was forgotten and lets you correct the minutes before saving. **Add time already spent** takes a category, a day (today, yesterday or a date, never the future), a start time and minutes; the end follows. An entry is at most 1440 minutes and counts on the day it *started*, in the server's zone.
- **Totals**: Today · 7 days · 30 days · All, an area filter, and Me · Everyone. On the compare area (Home) with two or more people: hours and shares head to head, the split bar, how many days each person logged something, the per-category bars, and **Guess your share**, where the other person's guess stays hidden until yours is locked in. With two or more people Totals opens there, at 30 days, and the comparison and the guess card stay up with nothing logged yet (each person at *0m · nothing logged*, a guess can come first); only the per-category bars give way to the empty state (#463). People differ by initials and by fill (solid, hatched), never by colour. **Download CSV** exports exactly the entries the totals sum (`GET /api/time/entries.csv?period=` or `?from=&to=`, plus `area`, `person`).
- **History** lists every entry by day with its clock range (`09:10 to 10:40 · 1h 30m`) or, for an imported entry, its duration alone. Tap a row to edit it, whoever logged it: person, category, day, start, minutes, note. A timer belongs to whoever started it, so moving an entry to the other person is how a mis-credited one is fixed. The row menu also has Start again, and Delete (confirmed).
- **Categories**: areas (seeded Home, Work, Personal, Health) hold categories (Home seeded with ten household ones, every other area with *General*). Settings → Tools → *Time categories* adds, renames, reorders, moves a category to another area, and archives. A category's add and *Edit* dialogs carry its **subtitle**, the line under its name in Log and Settings (up to 80 characters; emptying it clears it, #463). An archived area or category leaves the start list and the pickers but keeps its past entries in History and Totals. Only a category made by mistake can be deleted: its row menu offers **Delete** (behind a confirm) while no entry and no running timer points at it, and the API refuses any other delete with 409 `category_in_use` (#463).

## Pushing entries from another app

Another app on the PC (or the tailnet, with the bearer token) can keep its own time in task-os without tracking ids, by naming each entry with a `source_id` of its own (#469):

- `PUT /api/time/entries/by-source/{source_id}` with `{person, category_id, day, minutes, note?}` creates the entry (**201**) or replaces those fields on the one that already has the key (**200**). It is a duration-only entry, so a `start` is refused (422), and every other check is a hand entry's: a configured person, 1–1440 minutes, no future day, a category that is not archived, a note of at most 140 characters. Re-sending what is stored changes nothing, `updated_at` included, so a nightly re-push of the last few days does not churn.
- `DELETE /api/time/entries/by-source/{source_id}` removes it (**204**, **404** when none has the key), for a day the app now counts as zero.
- `source_id` is `<namespace>:<id>` — a lowercase namespace, a colon, then 1–120 of `A-Za-z0-9:._-` (for example `usage:app-launcher:2026-10-14`) — and anything else is a 422. The colon keeps the keys apart from the prototype importer's document ids.
- **The pushing app owns the entry.** A hand edit of a pushed entry in the Time tab is overwritten by the next push, and a hand delete is recreated by it. Entries with no `source_id`, and the importer's add-only rows, are never touched by either route.

Both routes sit behind the same gate as the rest of `/api/`: a caller on the PC needs no credential, any other client needs the bearer token.

## Importing the prototype

`scripts/import_time_prototype.py <export dir>` imports the time prototype's database export (`entries/`, `guesses/`, `timers/`, one JSON file per document). It is idempotent on the document id (a second run inserts nothing), writes in one transaction, keeps imported entries duration-only (the prototype never recorded a start), never overwrites a guess already changed here, and does not import running timers. An export naming a person not in `time.people`, or a category outside Home, is refused with exit 2 and nothing written; `--skip-unknown-people` skips and counts those rows instead. Rows the prototype's own totals ignored (minutes not above zero, a malformed date) are skipped and counted, and possible save-retry duplicates are listed by id, never deleted.

**Cutover**, once: stop every timer in the prototype; re-export its database into a new dated folder (a Claude session lists each collection with `ArtifactData` into an `out_dir`); run the importer against a scratch copy first (`TASKOS_DB_PATH=<temp copy>`) and compare the Home totals with the prototype's; run it for real; stop using the prototype.
