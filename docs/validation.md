# Validation — every step is a user story, proven on screen

Technical green is not enough. Each build step (a "Step N/13" issue) has a story — the sequence a user actually performs — and the step is done only when that sequence has been (a) walked by the automated Playwright test `tests/e2e/test_story_NN_<slug>.py`, which saves numbered screenshots, and (b) walked live on screen with the same shots kept here as proof. Phases are keyed on **Steps**, not story numbers, and close with a full storyboard re-run (Phase A: Steps 1–7; B: Steps 8–10; C: Steps 11–13 — #12, #13, #14). Stories 01–10 are Steps 1–10, one to one; from 11 on, a story number is simply the next free one, taken in order by the enhancement stories written after Step 10 — so story 11 is #77, not Step 11, and a Step 11–13 story will take the next free number when it is written.

Rules: screenshots come from a **synthetic / empty fixture**, never real data (this repo is public); real-data checks are walked too but their shots go on the private issue, not here. `[x]` means "walked and seen". Anything that could not be walked is written **not verified**, never as passed.

## How a story shot is captured

The gallery is only proof if a change in it means a change in the app, so a story shot has to be reproducible in two senses: two runs of `tests/e2e` against one commit produce the same files, **and** a run next month against unchanged code still produces the files the repo is holding. Five rules, and a new story inherits all of them by following them (#134, #166, #225):

1. **Capture through `shot(page, shots / "story-NN-<slug>-<n>-<device>.png")`**, never `page.screenshot` directly. `tests/e2e/conftest.py`'s `shot()` settles the page first — network quiet, fonts and images loaded, every finite animation finished (the vendored nav's boot reveal starts 1.8 s after load), scroll offsets and DOM size unchanged for three frames — and then captures with Playwright's `animations="disabled"`.
2. **Never screenshot an absence without first asserting a presence.** "The blocked task is not on the Board" is only evidence once the Board has rendered its rows; asserted on its own it passes against an empty pane, which is how a blank board was once committed as story 20's proof.
3. **A pane put somewhere before the shutter opens must be checked it got there** — capture through `scroll_to_bottom(page, pane)`, never a bare `pane.scrollTop = pane.scrollHeight`. One assignment is made against whatever the content height is at that instant, and `settle()` cannot audit it afterwards: it waits for each scroller's *offset* to stop moving, and an offset left short of the end does not move. Story 08's drawer shot came back ~28 px short on a busy machine that way (#166), and the gallery could not tell that from a real change. The helper settles, scrolls, settles, and accepts the position only once the pane is genuinely at its end with a height that did not shift under it.
4. **Anything on screen that comes from a clock, a path or a build identity must be pinned.** The suite runs at one fixed instant, for good: `tests/e2e/conftest.py`'s `E2E_ANCHOR` is a frozen date (a Monday, in the recent past), `E2E_CLOCK` is that day at 09:00, and the seed anchors every due date on it, so the relative dates on screen (`in 9d`, `in 3w`) stay exactly as believable as they were on day one. It reaches the page by three different routes, and all three are needed: **`TASKOS_CLOCK`** pins the server (`src/clock.py`) — the activity rows, comments and `built_at` a story writes; **`context.clock.set_fixed_time`** pins the *browser*, because the dates a reader actually sees on a card are computed in the page by `format.js::relDue` off a bare `new Date()` that `TASKOS_CLOCK` never reached (conftest's `_pinned_browser_clock` wraps `Browser.new_context` so no story can forget it, and `shot()` refuses to capture a page whose clock it does not recognise); and **`TASKOS_BUILD_SHA`** pins the `Build:` footer to `e2e0000`, because an honest `git rev-parse` rewrote 19 shots on every single commit. Paths are pinned the same way: every instance works in a fixed directory under the system temp root rather than pytest's per-run `pytest-NNNN`. The one deliberate hole is a *natural-language* date: "next friday" is resolved by `src/dates.py`, which now reads `src.clock` rather than `date.today()` for the same reason (#225). **A toast is a clock too**: it dies on a `setTimeout` no fixture pins (4.5 s, 10 s with an action), and the stack reflows when the longest line leaves it, so a shot that does not mean to show one clears the stack with `dismiss_toasts(page)` first — story 24's dark report shot moved by 74974 px between two runs of one commit before it did (#166). A story that *does* mean to show a toast captures it young, right after the action that raised it. **A background poller's own schedule is a clock too**: `TASKOS_CLOCK` pins the timestamps a poller *writes*, but not the real `threading.Event.wait()` that decides *when* it writes one — a story that enables one (email capture, story 24's archive fixture) can have its first automatic pass land mid-story on a real 15 s timer, racing a manual action and rewriting a status card a shot already framed. `TASKOS_CAPTURE_DELAY_S` pins that poller's own first pass an hour out for every disposable instance for exactly this reason (#170: story-24-archive-9-desktop.png moved between two runs of one commit before it did).

5. **The gallery is a baseline, so something has to compare it.** `& .\.venv\Scripts\python.exe -m scripts.shot_determinism --check-tree` diffs whatever a run just rewrote against the bytes git is holding, reports what drifted, and restores the tree; `--baseline` runs the suite first. The pre-ship gate runs `--check-tree` as its last stage, so a verification run neither hides gallery drift nor leaves rewritten PNGs behind for the next person to remember to `git checkout`. Re-baselining is the deliberate counterpart: run `pytest tests/e2e` yourself, look at what moved, `git add docs/screenshots`, and say why in the commit message.

(The `Build:` footer on a shot reads `Build: e2e0000 · <the frozen anchor>` — a fixture, deliberately not a plausible SHA, so nobody reads it as the commit the shot came from. Before #225 it was the real SHA, which is precisely why the gallery could never be compared with the gallery in git.)

Check the capture with `& .\.venv\Scripts\python.exe -m scripts.shot_determinism`: two full e2e runs, then a diff. That answers "is the capture stable?" and, structurally, nothing else — both snapshots are fresh, so a shot that has been wrong in the repo for twenty commits compares clean against itself, which is how 76 of them drifted unnoticed (#225); rule 5's `--check-tree` is the half that catches that. It exits 0 only when no shot changed in a way a reader could see, and prints the two stated escapes every time — story 06's five shots (its instance runs on the real clock, because the mirror's import-conflict rule is *defined* by a clock that advances) and story 09's Settings shot (it shows the opener install command, which carries the instance's ephemeral port) — plus any shot that differed only as the rasteriser differs from itself — up to 2/255 across as many as 500 antialiased pixels, or at most 64 pixels off by up to 24/255, which is one icon stroke landing on the other side of a sub-pixel (the phone nav's search icon does this, to the pixel, in one run out of about three; the cause is #170's, still open). Both bands sit an order of magnitude below the smallest genuine change ever measured here — 35 px at delta 210, one digit of a timestamp.
