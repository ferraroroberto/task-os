## Why a checkbox and not the switch

The lint's `no-native-checkbox` contract is named after the fleet's one-boolean-control rule, and the obvious reading is "replace it with the vendored switch". That is the wrong control here and the issue says so: a switch is a **setting** you leave on. These are **selection** controls — you tick rows to act on them and the tick is gone a moment later — and a column of switches down a task list reads as "turn this task on". shadcn keeps Checkbox and Switch as separate components for exactly this split, so the fix models the Checkbox and leaves `switch.css` vendored and untouched.

## What this round did not do

**The `no-native-checkbox` contract still reports FAIL, and that is expected.** It is a string match for `type=["']checkbox["']` across the app's markup, and the only place that pattern appears is `app.js:1061`'s `input:not([type="checkbox"])` — a CSS selector in the keyboard handler, not a control. The three real sites build their inputs in JS (`box.type = 'checkbox'`), which the pattern never saw, so the contract was FAIL before this round for a reason unrelated to the finding and stays FAIL after it for the same reason. #129 already records this; it is a lint-precision matter for `fleet-config`, not an app defect.

**The `docs/screenshots/` story gallery is deliberately not refreshed.** Regenerating it turned up a determinism problem worth its own issue rather than a silent 94-file commit: running the e2e suite twice against *identical* code produces **9 of 152** screenshots that differ, some by up to 14%, and the `story-20-blocked-by-1-desktop.png` currently committed on `main` is a **blank board** captured before the first render landed. Refreshing the gallery on top of that would have buried this round's real visual delta — a 14×9px glyph and a checkbox skin — under unreviewable noise. The round's proof is the five hand-captured shots above; the gallery is a separate follow-up.

## Verification

- The five screenshots above: captured in a **headed** Chromium walk on the seeded disposable instance and read back one by one. The walk drove the real thing — Select mode on, two Board cards ticked, the theme toggled and back, the Table's own leading column, then the filter dropdown opened and a person ticked (the table filtered to one row on it, so the control is wired, not just painted).
- Geometry proven unchanged where it must be: with Select mode on and 39 rows rendered, the Table's row heights, table height (1949.47px), document height (1011px) and `.c-sel` column width (36px) are **identical** with the new `.check` paint and with it neutralised back to the native one. The restyle costs the desktop grid no layout at all.
- Computed styles read back live: every checkbox on the page carries `check` (16×16, `border-radius: 4px`, `appearance: none`, accent fill when ticked, 2px accent focus ring), across all three class combinations — `check`, `check trow-check`, `check row-check`.
- `scripts\verify-before-ship.ps1` green: byte-compile · ruff · **411 unit** · e2e full tier, **15 tests**. The first e2e run failed on `test_story_07_phone` with blocked-request page errors and passed on a re-run and on two further full runs — a flake in that story's second phone context, unrelated to this diff (which is CSS plus one class name per site).
- The lint that filed the round, re-run on the fix (`design_lint contracts`): `icon-sizes` goes **WARN → PASS** (the 12px pair is gone), and `row-height-scale`'s stray list goes from `16/12/20/6/30/32/24px` to `30/34/6/24/32/20/18px` — the checkbox's 16px, the chip glyph's 12px and `.trow`'s 64px all leave it, and what remains is the icon/glyph dimensions inside row-named selectors that #129 already read as coincidental name matches. The two WARNs #129 called non-findings (`desktop-measure` 767px, `icon-set`'s `⌘`) are unchanged, as is the `no-native-checkbox` FAIL discussed above.
- The 4px radius is `calc(var(--radius-sm) / 2)`, not a literal: the fleet scale bottoms out at `rounded.sm` 8px, and 8px on a 16px box is a circle, which reads as a radio button. Derived from the token rather than hardcoded, so it still counts as tokenized and moves with the scale.
- Not verified here: the same walk on the real phone over the tailnet (owner-only — the standing item in [validation.md](../validation.md)'s owner checklist).
