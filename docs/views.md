# Views

PC-first: Board and Today are two-dimensional (lanes, a calendar lane) and span the window, declared in `.fleet.toml` (`[design] wide_views`), while Time, Search and Settings are one-dimensional and keep the centred 772px measure (design.md Layout) — a Settings sheet then opens beside the list as the detail pane, and the Email archiving report, a nine-column table, spans the window; the phone gets the same views as an adaptive second rendering (bottom pill, the archiving report as cards, drawer and Settings sheets full-screen). The nav holds four destinations (Today · Board · Time · Search); Settings is the gear in the header, one tap from every tab, and the batch-archiving report is its *Email archiving* row. The Table tab — a grid and a Tree outliner — is gone; a stored `table` / `tree` tab or an old `#table` link lands on Today.

- **Today leads, and is where the app opens** — the nav reads **Today · Board · Time · Search** (Settings is the header gear; Time, see [Time tracking](time-tracking.md#time-tracking)), on the phone's bottom pill and the desktop rail alike, and a first visit lands on Today on every pointer. A deep link (`#task/<id>`, `#search`, `#journal`, `#settings/…`) still wins over the landing tab, and the last tab you left is remembered per browser (`task-os.tab`), so only a fresh browser opens on Today.
- **One row, one filter state, every view** — Board, Today and the Search tab's task hits are *renderings* of the same filtered list, drawn with the same row (`rows.js`), the fleet's vendored **action-row**: a leading **completion circle** on a mouse or trackpad (complete an open task — a recurring one rolls to its next date — or reopen a closed one, with Undo; a touch screen has no circle: a task closes by swiping it right, or by opening it and setting its status, and the keyboard's `e` works everywhere), the one-line ellipsized title over **one quiet meta line on a budget** — due (relative, with the repeat glyph when it recurs; overdue and due today in the attention tone) · **exception chips only**, neutral, in the one status-chip tone map: *Blocked* or the day a snooze ends (clock glyph), an *Inbox* / *Standby* status where the view does not already say it, and *High* (no mark for medium or low, no danger tone) · **one** context name, the only part the ellipsis may take: the project when the view does not group by it, else the issue code · at most two counts, children and comments, kept outside the ellipsis. The folder, AI conversation and issue links and the person are not on the row: the ⋯ menu opens each link and the drawer shows them all. On a mouse or trackpad every open row outside the Board's lanes also shows **Move** — the one visible verb (a calendar glyph on a 44px icon button between the title and the kebab, unpainted like the kebab), because re-dating is most of what gets done to a task: one click opens the date sheet, one pick moves it. Then one trailing **⋯ kebab** holding every other action (Move…, snooze, status, priority, open folder / AI conversation / issue, details; also right-click, `.` or the menu key on a focused row). **On a touch screen a row swipes** (`swipe.js`): right completes it (with Undo), left opens the date sheet to move it — never the only way to do either, and never in the phone Board's Status carousel, whose columns swipe sideways already; on the phone the rows run edge to edge. Nothing on the meta line is a target, so a tap anywhere on the row opens it; 60px a row. Flat hairlines between rows, no card boxes. Above every view sits a **top strip** on one line — the live **text filter**, always on screen because it is the one reached for most, with the **filter button** beside it, then *Select* and the quick-add `+`. The list's count is the text field's placeholder (*Filter 12 tasks…*), its one home; the filter button carries how many filters are on (and its name spells them out — *Filters, 2 on: todo · Home renovation*) and opens the **filter sheet** (`filters.js`, the vendored editor modal): **sort** first (due · priority · last modified · created · title), then **status (ticks, several allowed, incl. `done` / `cancelled`, so finished items are findable)**, project, **person (ticks, several allowed)**, due window and modified window (incl. its inverse — **untouched > 30/60/90 days**, the weekly stale pass: do it, defer it with a start date, or admit it's dead; any write counts as a touch, sync and mirror included, so a GitHub-synced task never looks stale), applied as they change, with *Clear* beside *Done* while something is on; on the phone the ticks sit two per line. The state **is the URL** — `?status=todo&project=12&sort=updated&updated=week` is the same shareable view on every tab; the default is open tasks (plus today's done tasks for the Board's last column). Today, the Board and Search carry a **Tasks · Issues · All** switch on the line under the strip (the vendored segmented control): **Tasks** (the default) leaves out the issues the forge sync brings in, **Issues** shows only those (a task carrying an issue ref), **All** both; the pick is the URL's `?scope=` (absent for Tasks), so it survives a reload, and the filter sheet's *Clear* leaves it alone. **Whose tasks.** With two or more members (`people` in the config), Today and the Board carry a second switch, **Mine · Everyone**, on the same line: **Mine** (the default) is the tasks whose owner is the person this device is signed in as — each phone signs in with its own token, so it opens on its own tasks with no picker step; plain loopback on this PC is the install owner, and a task nobody gave an owner counts as the install owner's — **Everyone** every member's. It is the device's: remembered under the `task-os.whose` key (Mine when the store is unreadable) and mirrored into the URL as `?whose=everyone` (absent = Mine), so a shared link says what it shows; an explicit `?whose=` beats the stored pick, and reading a link never rewrites it. It is the other axis from the scope, not part of it; the filter sheet's *Clear* leaves it alone; the journal follows it. **Search always covers everyone** — the Search tab's task hits ignore it (the other filters still apply), it shows no Mine · Everyone control, and the command palette searches everyone too. With one member there is no switch and nothing changes but the scope's label. The narrowing is the list API's own `?owner=` filter, so the counts and the journal's older-weeks probe agree with what is listed. Today's horizons sit under quiet uppercase section headers with their counts, and a project sub-header is drawn only where two or more groups need telling apart — otherwise each row names its own project. **Move** (the row's verb, its swipe left, the menu's *Move…*, the `d` key and Select mode's Move) opens the date sheet: *Tomorrow · This weekend · Next week · Today* — the push-outs first, since most re-dates push a task out — each with the date it lands on beside it (`GET /api/dates`), then *Pick a date…* and *No date*. A status beside a title (a child, a blocker, a palette hit) is a chip only when it is an exception — an Inbox arrival (accent), standby (neutral) — in the one status-chip tone map; todo and done are a quiet word.
- **Board** — a **week planner**, with the status columns behind a segment. The line under the strip holds the **Mine · Everyone** switch (two or more members), the **Tasks · Issues · All** switch and **Week · Status** (the vendored segmented control; the pick is remembered on the device, `task-os.board.mode`; on a phone the first two switches take a row and Week · Status the next). **Week**, the default, lays the open tasks out by due date: **Today** (overdue included) · **Tomorrow** · **This week** · **This weekend** · **Next week** · **Later**, the tasks with no date closing *Later* under a *No date* sub-heading. A week runs Monday to Sunday (on a Sunday, "this week" is the one tomorrow starts), and *This week* and *This weekend* are there only while they have days left after tomorrow, so every date has exactly one lane. **Drag a row onto another lane** to re-date it to that lane's first day (the Move sheet's *No date* clears a date): it is the date sheet's own Move, with the same toast and Undo, and nothing but the due date changes. **Status** shows **Inbox · Todo · Standby · Done today** (done today = completed on the current local day; tick `done` in the filter sheet to see all done tasks instead); drag a row onto another column to change its status, and status ticks hide the columns not picked. In both modes an empty lane collapses: to its header on a wide screen, where it is still a drop target, and out of the way on the phone. On a wide screen (≥ 1024 px) the lanes sit side by side using the full width, each scrolling on its own under a sticky header with its count; the six week lanes share the window and never scroll it sideways, a long title shortening with an ellipsis instead. On the phone Week is one list of lane sections (the rows swipe there) and Status a one-column scroll-snap carousel whose count strip doubles as the column switcher. Flat regions split by 1px hairlines. The page header names the Board's exceptions: Inbox arrivals in the accent, then what is overdue or due today (*4 in Inbox · 3 overdue*).
- **Select several tasks at once** — the checklist toggle in the Board's and Today's top strip turns every card/row into a tick target (drag is off while it is on, and a tap on the phone selects rather than opening — the horizontal swipe still belongs to the Board's carousel). It is **one selection**: tick three cards on the Board, switch to Today, and the same three are ticked there. With at least one ticked, the bulk bar takes the top strip over, on **one line** with every control at the strip's own square height — *N selected* · **Move** first, as on the row (the one date sheet — the push-out phrases with their dates, *Pick a date…*, *No date* — so a pick moves the whole selection) · **set status** (`complete` included, so a recurring task in the selection rolls its due instead of closing, exactly as its own row select would) · **Set owner…** (only with two or more members: a person-glyph square whose pick hands the whole selection — a project's children, say — to that member) · ✕ to leave. On a phone with the owner square showing, the count drops the word *selected* so *Set status…* stays readable. One `POST /api/tasks/bulk` per action, applied through the same repo layer as a single-task edit, so every task gets its own activity row. A task that fails — deleted in another tab, say — is **named in the toast** (`1 updated · 1 failed (#36: …)`), never dropped in silence; Escape leaves Select mode. The bar's fourth square is **delete**: one confirmation names the count (and how many are projects whose children go too, and how many are synced coding tasks the next sync would bring back), then `POST /api/tasks/bulk/delete` with the same per-id report.
- **One key per action** — with a row focused, `e` completes, `1`–`3` set the status, `t` / `w` set the due date, `s` snoozes, `p` cycles priority, `z` undoes, `?` lists them; with tasks ticked the same key acts on the whole selection. See [Keyboard triage](task-workflow.md#keyboard-triage).
- **Done journal** — everything closed, newest day first, one flat heading per local calendar day (`Yesterday · Tue 1 Sep · 2 done`) over the same rows (the filled circle reopens a task in place); cancelled tasks ride along muted, with a switch in the head to drop them. A reading surface, not a tab: open it from the command palette (*Journal*) or the **journal** link in the Board's Done column head — `#journal` deep-links it (`#journal/task/42` with the drawer open), the shared filter sheet applies and rides the URL (project · person · text; status, due, modified and sort are hidden because they say nothing about a closed task), and any tab press leaves. The page is this week; **Show the week before** widens it seven days at a time, and the journal only says it has reached the end once the server confirms nothing closed earlier. Friday afternoon it answers "what actually happened this week"; the weekly review will quote it. `done_at` is the **closed-at** stamp — set when a task enters `done` *or* `cancelled`, cleared when it reopens (schema v10 backfills cancelled tasks from their activity log) — and the day is the local calendar day, the same rule as the Board's *Done today*. Terminal: `tasks journal [--weeks N]`.
- **Today** — every open task, in four horizons nearest first (with the Table gone, this is where any open task is found, by the text filter, which works across all four, or one tap on a folded horizon): what is **due** — ≤ today, overdue first, then today — then **Soon** (tomorrow … +7 days), **Later** (further out) and **No date**, each grouped by root project, sorted by due date within each group (same as every other view — a schedule change always reorders it), the same rows (status changed through the select — a recurring task also gets a **complete** option that rolls its due one cadence forward instead of closing; **done** always closes for good, recurring or not); group titles in the app's normal title font. The tab opens on what is due: those rows come first with no heading of their own, because the page header names them — *2 overdue · 3 due today* in the attention tone, or a muted *Nothing due today* — read off the very counts the list was drawn from, so the header and the list never disagree. The header no longer repeats an open count on any tab; the other views name their own exceptions there as the redesign reaches them. Each row also reaches **snooze** from the ⋯ menu's *Snooze* entry (or the `S` key) — *Tomorrow · This weekend · Next week · Pick a date…* — which sets the task's start date and takes it off the list, with an Undo in the toast (see [Start dates & snooze](task-workflow.md#start-dates--snooze)). **Soon**, **Later** and **No date** sit below as flat disclosures with their counts: Soon open, Later and No date folded until you open them (a re-render keeps them as you left them, a reload folds them again, and a text filter opens them so a match is never hidden); Later and No date only show when they hold something. This is the landing tab on every pointer (the last tab is remembered after that). **On a desktop window (1024px and up) Today is a split view**: the list takes the left half and the right half is the task detail, so a row's ⋯ menu sits near its title rather than at the far edge of the window. The right half is never empty while a task is due: arriving on Today with nothing open shows the first due task there by itself, without writing a `#task/` link (a reload picks the first due task again), and the row keys keep working beside it; leaving Today closes it. Opening a task (a tap, Enter, or ⋯ → *Open details*) fills the half with the same drawer the other tabs use, `#task/<id>` still deep-links, and closing it reads *Select a task to see its details*. The Board keeps the 440px side panel, and the phone keeps the full-screen sheet.
- **Task drawer** — a right-hand side panel on desktop (≥ 1024 px, the list stays visible beside it), full-screen on the phone; deep-linkable as `#task/42`. Ordered by how often each part is used: most edits push a due date out, so **Due comes first**, with the date sheet's phrases under it as one-tap **quick moves** — *Tomorrow · This weekend · Next week · Today*, push-outs first, each with the date it lands on (the same `GET /api/dates` answer the row's Move uses); typing a date or the calendar button still works. Breadcrumb (clickable), with a quiet line under it — **Change parent**, and **Remove parent** when the task has one — → editable title (a field with a visible boundary) → **Due** + quick moves → status and priority (and **Owner**, with two or more members — see below) → **Links as pills**: the folder, the linked issue and every link on one row, there to open (an AI-conversation URL wears the bot chip — see [AI conversation links](ai-conversation-links.md#ai-conversation-links)) → description (markdown, edit/preview) → comments newest-first with URLs / `{folder}` refs / `repo#N` as clickable chips + a composer (Ctrl+Enter sends, `origin = ui`); every comment carries a **pencil** that opens the body in place (Ctrl+Enter saves, Escape cancels; the author, time and origin are untouched, an edit corrects the text and never re-attributes it) and a **trash** that asks first, since there is no undo → activity log (`field old → new · actor · time`), where the issue sync's rows fold behind one *Show N sync updates* toggle so your own changes lead → **More fields**, a disclosure closed by default whose summary names what is set inside (*starts in 3d · repeats · 1 blocker*); once opened it stays open for the page's life, and a reload closes it again. Under it: starts, repeat (+ every N, + the fixed day), person, code, the folder editor, the link editor (label edit, remove, add), blocked by, children (click to navigate, add child) and the **issue panel**: the linked issue (provider glyph, `repo#N` chip, state, labels, last synced, *Sync now*, *Unlink*) or, for a plain task, *Create issue* (repo from the last-seen list or typed) and *Link existing* (`owner/repo#N` or the URL). See [Issues as tasks](issues-as-tasks.md#issues-as-tasks). Last, quiet, at the foot: **Delete task** — a confirmation names the task and, when it has one, its subtree (*Its 3 child tasks go with it*); confirm and the task is gone with its comments, links and history (no trash, no undo — the dialog says so), the drawer closes, every view refreshes, a toast says how much went. A **synced coding task whose issue is still open** gets a warning in the same dialog: the next issue sync recreates it while the issue stays open, so unlink it first or close the issue — the delete is still yours to confirm, but never a silent resurrection ten seconds later.

  **Changing or removing a parent.** The line under the breadcrumb holds **Change parent** (accessible name *Change parent of <title>*) and, only when the task has a parent, **Remove parent**. Change opens a picker sheet — a centred card on a desktop, the whole screen on a phone — with a filter field whose placeholder counts the tasks (*Filter 44 open tasks*) over every **open** task in tree order, indented by depth, each with its path as muted text; the task itself, its descendants and closed tasks are not offered, and any open task can become a parent (it turns into a project the moment it has a child, and stops being one when the last child leaves). A tap, or Enter on the filter's first match, files the task there through `POST /api/tasks/{id}/move`; Remove parent sends `parent_id: null` with no confirmation and no Undo. The server stays the authority — a target that became a descendant while the picker was open is refused with a `cycle` toast. This is the one way to re-parent from the UI; the old *Move to* select under More fields is gone.

  **Whose task it is.** Every task has an **owner** — a member of the install (`people` in the config), not the drawer's *Person* under More fields, which stays the contact a task is *about*. With two or more members the drawer's head carries an **Owner** select beside status and priority, on the desktop panel and in the phone's full-screen drawer: pick another member and the task is theirs at once, with an `owner old → new` row in the activity log (by name). A new task is owned by whoever made it — the member whose own token signed the request, or the install owner at this PC — and a subtask by its creator, not its parent. A task nobody ever gave an owner (everything from before schema v20, a synced issue, an email capture) is the install owner's. With one member there is no control at all.
- **Settings** (the header gear) — five inset groups (design.md `settings group`): **This device** (Text size, changed in place · Row actions · Command palette · Phone access), **Sync** (Issues as tasks · Calendar), **Email** (Capture into Inbox · Email archiving), **Tools** (Time categories · Search · Folder opener · Voice quick-add · AI Inbox triage) and **This install** (Database · Mirror and backup). Each row shows its current value — *on* · *synced* · *off* · *3 filed* …, in the attention or danger tone when it is an exception — and its chevron opens the row's **sheet**, which holds the card that row replaced, every control and reading unchanged. On a desktop window (1024px and up) the sheet is the detail pane beside the list (list : detail = 1 : 1.5, the selected row tinted); on the phone it is full-screen with × and **Done**. `#settings/<row>` keeps a sheet open across a reload, and Back closes it. The header line names what needs you: the mails the last archiving run left (*3 mails need you*), then a failing service (*Issue sync failing*, *Backup failing*), else a plain *6 of 9 services on*.
- **Settings → Email archiving** — the one surface that is not a rendering of the task list: the sheet carries the *Archive Inbox now* button, a **first N mails** bound (empty = the whole Inbox), the archiver's own state (configured / running / the model it ranks with / the last run / *not configured* with the reason) and what the runs on the picker add up to. Under it, the chosen run as a table — on a desktop window the sheet spans the content width for it rather than taking the detail half — — subject (with who · when under it) · destination (the last three path components, the full path on hover) · files (each `.msg` a chip that opens through the [per-PC opener](folders.md#folders-that-open-on-any-pc); the first one shown, the rest behind a *+N more* chip that opens them in place) · confidence · why · state — and behind each row's **⋮** exactly the review levels that row's state allows (a row carries its file chip, *+N more* and the ⋮, nothing else): **Accept** (a mail that needed a human), **Move to… / File it…** (the candidates the run already ranked, or any other folder through the same index picker the drawer uses, with an optional one-line hint the next run remembers), **Retry** (on the one row whose file was written before Outlook refused the move: one tap re-sends the same decision and the mail leaves the Inbox) and **Revert** (the files are deleted and the mail goes back to the Inbox). A run picker lists earlier runs; *Accept all N that need you* clears a reviewed batch in one go; every action that touches a file asks first. The phone gets the same report as cards with the actions behind each row's *Review* — and the whole pane is drawn for 390 px: the head is one line with the three readings one line each under it (bold lead word, muted tail, the whole reading in the title), the run picker reaches the right edge with the bulk button full width under it as *Accept all (N)*, every review level is a plain glyph-only icon-button (`.archive-action`, its word the accessible name and tooltip — nothing outlined or filled at rest) with **Revert** alone behind the card's ⋮, the *File it…* panel puts the folder field's glyph inside its own right edge over a full-width *Archive here*, and nothing — a long subject, a deep path in a reason — can make the pane scroll sideways. The command palette's *Go to Archive* says **N mail(s) from the last run need you** when the last run left something undecided. See [Archive the Inbox](inbox-archive.md#archive-the-inbox).
- **Search** — one box over four indexes (tasks · folders · emails · issues), results as one card per kind, in the centred 772px column; each row opens, attaches to the task in the drawer, or becomes a task. `Ctrl+K` / `⌘K` opens the **command palette** from any tab: type to jump to a task, `>` for commands. See [Search everything](search.md#search-everything).
- **Text size** — Settings' *Text size* row, changed in place: Small / Default / Large (the vendored `text-size` control as a vendored `segmented` group, from project-scaffolding), the escape from the viewport zoom lock for anyone who needs bigger text. It scales the root font-size (93.75% / 100% / 112.5%), so every rem-based type role grows with it while rows, buttons, the nav and icons keep their pixel geometry. The step is stored per device in `localStorage` (`task-os.textsize`) and stamped on `<html data-textsize>` by the inline pre-paint script in `index.html` — the same script that stamps the theme — so a reload paints at the chosen size with no flash.
- **Row actions** — Settings → *Row actions* (its sheet): what a **swipe right** and a **swipe left** on a task row run (any row action, or nothing; the plan's defaults are *complete* and *change date*), and which row actions the **⋯ menu** lists and in what order (tick, ↑ / ↓; *Reset to the defaults*). The choices are ids from the one action table (`actions.js`), so the swipes, the menu, the keys and the palette stay one source. An action a swipe runs is always kept in the menu, and every action keeps its key and palette entry, so none is ever gesture-only (WCAG 2.5.1). Stored per device in `localStorage` (`task-os.rowactions`, `rowprefs.js`), like the text size.
- **Quick-add** — the `+` in every pane's top strip (Board / Today) opens one dialog: line 1 is natural language, parsed server-side by `POST /api/parse` (so the CLI and the UI agree) — the dates it finds land in the **Due** and **Starts** fields where you can still correct them, the parent shows as a chip. Under it sit the fields worth setting while the task is still in your head, all optional and empty by default (no date, status `todo`): **description**, **due**, **starts**, **status**, **folder** (typed as a ref / an absolute path, or picked from the folder index — the same picker the drawer uses) and **one link** (url + label; its kind is classified the same way the drawer classifies a pasted link). `type · Enter` is still the whole fast path. Escape, the backdrop and the × discard the draft; Escape closes the folder picker first when it is open:

  | You type | Result |
  | --- | --- |
  | `renew passport next friday` | title `renew passport`, due = next Friday |
  | `pay water bill by tomorrow` · `… on fri` · `… in 2 weeks` | trailing date phrase (optional `on` / `by` / `due` lead-in) — every phrase `src/dates.py` knows |
  | `renew insurance due oct 15 starts oct 1` | both dates off one line — `starts` needs its keyword, a bare trailing date is the due date ([Start dates & snooze](task-workflow.md#start-dates--snooze)) |
  | `order sensor #12` | nested under task 12 |
  | `order sensor › garden-bot` (or `> garden-bot`) | nested under the open task whose title matches (exact title wins, then a task that already has children) |
  | `fix tap › Bathroom tomorrow` | parent **and** date |

  A parent that matches nothing shows as a red chip and nothing is created. Enter creates the task and focuses its row.
